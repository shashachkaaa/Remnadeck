# RemnaDeck 0.4 — панель мониторинга и управления для Remnawave

Отдельная веб-панель рядом с Remnawave: Docker, данные по API Remnawave, доступ по твоему домену
через реверс-прокси. Все настройки хранятся в `.env` рядом с `docker-compose.yml` — панель сама
пишет туда всё, что ты меняешь в вебе.

## Разделы

- **Обзор** — ноды на связи, путь до хостов, онлайн, сбои за сутки, трафик по часам, нагрузка, события.
- **Ноды** — статус, трафик, версия Xray; создание, правка, удаление, перезапуск, включение,
  выключение, а для привязанных серверов — обновление, Hysteria2 и CDN прямо из строки.
- **Хосты** — то, что клиент видит в подписке: создание, правка, включение/выключение, удаление.
- **Порядок нод и хостов** берётся из Remnawave (`viewPosition`) и меняется перетаскиванием за
  ручку слева — новый порядок сразу уходит в панель, `POST /api/nodes|hosts/actions/reorder`.
- **Серверы** — SSH-доступ к машинам с нодами: проверка, обновление ноды, Hysteria2, состояние CDN.
- **CDN** — шаблоны nginx и настроенные домены: выпуск сертификата, конфиг, снятие.
- **Задачи** — что панель делала на серверах, с полным логом выполнения.
- **Здоровье пути** — по каждому хосту Remnawave: DNS → порт → TLS с SNI, срок сертификата.
- **Пользователи** — поиск, фильтр по статусу, включение/отключение, сброс трафика.
- **События** — сбои, восстановления, действия администратора (с дублем в Telegram).
- **Прослойка подписок** — правка подписок на лету: значения RemnaDeck в текстах Remnawave, пометка упавших нод.
- **Баны** — по HWID и IP: забаненному прослойка отдаёт заглушку вместо подписки.
- **Автоматизации** — условие → действия с откатом: пороги квот, срок подписки → сквады, сообщения, скрытие хостов.
- **Статус-страница** — публичная страница состояния нод для клиентов на отдельном домене.
- **Настройки** — подключение к Remnawave, уведомления, интервалы опроса, учётная запись.

## Установка

Одной командой на сервере с Remnawave (от root):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/shashachkaaa/Remnadeck/main/install.sh)
```

Скрипт скачает проект в `/opt/remnadeck` (другая папка — `REMNADECK_DIR=/путь` перед командой),
при необходимости поставит Docker, спросит домен, создаст `.env`, соберёт и поднимет контейнер,
допишет домен в Caddyfile Remnawave (если найдёт) и напечатает **код первого входа**.
Открой домен — мастер попросит код, логин и пароль администратора, адрес и токен Remnawave,
по желанию Telegram. Всё сохраняется в `.env`, пароль — только хешем (scrypt).

Если Docker Hub с сервера недоступен, базовый образ берётся с зеркала (`mirror.gcr.io`, Timeweb).

Забыл код: `grep SETUP_TOKEN /opt/remnadeck/.env` или `docker logs remnadeck`.

## Версия и обновление по кнопке

Рядом с логотипом — значок версии. Он светится, когда на GitHub есть новые коммиты, и
жёлтый, если на сервере стоит локальная версия, которой ещё нет на GitHub. По клику — окно
«О панели»: коммит, дата сборки, список изменений и кнопка «Обновить».

Кнопка работает через systemd на хосте (ставит `install.sh`): панель кладёт `data/update.request`,
юнит `remnadeck-update.path` запускает `deploy/updater.sh` → `install.sh --update`. Контейнеру не
нужен доступ к Docker. Панель показывает лог обновления и перезагружается сама, когда новая версия
поднимется. Подписки на время перезапуска Caddy отдаёт напрямую (запасной путь).

## Обновление

Та же команда. Код заменяется свежим с GitHub, `.env` и `data/` не трогаются:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/shashachkaaa/Remnadeck/main/install.sh)
```

Из папки проекта — `cd /opt/remnadeck && sudo bash install.sh` (пересобрать без скачивания).

## Обновление с 0.2

```bash
cd /opt/remnadeck
# замени файлы новыми, .env и data/ не трогай
sudo bash install.sh        # допишет CRYPT_KEY, если его нет
docker compose up -d --build
```

Новые таблицы в `data/panel.db` создадутся сами. Ничего из старых настроек не теряется.

## Обновление с 0.1

```bash
cd /opt/remnadeck
# замени файлы новыми, .env и data/ не трогай
rm -rf agent
docker compose up -d --build
```

Старый `ADMIN_PASSWORD` из `.env` при старте превращается в хеш, логин остаётся прежним.
Если хочешь пройти мастер заново — удали из `.env` строки `ADMIN_USERNAME` и
`ADMIN_PASSWORD_HASH`, перезапусти контейнер и возьми код из `docker logs remnadeck`.

## Сбросить пароль

Удали из `.env` строку `ADMIN_PASSWORD_HASH`, выполни `docker compose restart`,
открой панель — снова запустится мастер (код в `docker logs remnadeck`).

## Что панель умеет через API Remnawave

- **Ноды** — создание, правка, удаление, перезапуск, включение/выключение, сброс трафика,
  порядок (`viewPosition`), перезапуск всех.
- **Хосты** — полный набор того же, включая порядок.
- **Пользователи** — создание и правка (срок, лимит, стратегия сброса, сквады, Telegram, e-mail,
  тег, описание, лимит устройств), удаление, включение/выключение, сброс трафика, перевыпуск
  подписки, устройства HWID (список и сброс), массовые действия над выбранными: сброс трафика,
  перевыпуск, продление, замена сквадов, удаление.
- **Сквады** — список, создание, правка набора инбаундов, удаление, добавить всех/убрать всех.
- **Инструменты** — генерация пары ключей x25519 для Reality, шифрование ссылки для Happ,
  статистика трафика панели и устройств.

## Закреплённая шапка

Всегда видна при прокрутке: кнопка меню (на телефоне), название раздела — появляется, когда
крупный заголовок уехал за край, — и быстрые кнопки: пинг до Remnawave (красный, если связи нет;
тап — настройки подключения), фиолетовый индикатор идущих SSH-задач (тап открывает лог текущей),
колокольчик со счётчиком сбоев за сутки и обновление раздела.

## Живые инструменты

- **Терминал** — полноценный shell на сервере ноды прямо в браузере (xterm.js по WebSocket,
  PTY через SSH). Под окном — ряд клавиш, которых нет на телефонной клавиатуре: Esc, Tab, Ctrl+C,
  стрелки. xterm.js лежит в самой панели (`static/vendor`) и подгружается только при первом открытии — без внешних CDN.
- **Лог ноды** — `docker compose logs -f` в реальном времени, с фильтром, паузой и подсветкой
  ошибок и предупреждений.
- **Из России** — TCP-проверка хостов, нод и CDN-доменов с точек check-host.net в российских
  сетях. Показывает блокировку по IP или порту; блокировку протокола (DPI) не покажет.
- **Сертификаты** — `certbot certificates` со всех серверов разом: сроки, истекающие и
  истёкшие, продление одной кнопкой.
- **PWA** — панель ставится на телефон как приложение («Добавить на главный экран»).

Терминал и лог работают через WebSocket. Caddy проксирует их сам; для nginx нужны заголовки
`Upgrade` и `Connection` — они есть в `deploy/nginx.conf.example`. WebSocket проверяет и сессию,
и Origin: чужая страница открыть терминал не сможет, даже если у тебя открыта панель.

## Квоты на группы нод

Термины: **сквад с лимитом** — сквад с инбаундами нод, на которые действует квота; его участники
под квотой. **Запасной сквад** — выдаётся вместо него при исчерпании.

Лимит трафика на пользователя, который считается только по выбранным нодам. Пример: Нидерланды
и Германия без ограничений, а на «Обход 1» и «Обход 2» — 300 ГБ в месяц на человека.

**Как устроено.** С заданным интервалом — по умолчанию раз в 10 минут, меняется кнопкой с часами в разделе «Квоты» (от 1 минуты до суток, применяется сразу) — панель берёт из
`/api/bandwidth-stats/nodes/{нода}/users` трафик всех пользователей по каждой ноде правила за
текущий период и складывает. Кто превысил — у того «сквад с лимитом» меняется на «запасной сквад», а активные соединения на нодах с лимитом рвутся (`/api/connections/drop`), чтобы клиент
не докачивал по уже открытому туннелю. Остальные сквады пользователя не трогаются. Обратная
замена — в новом периоде или сразу, как только человек перестал превышать лимит (например, лимит
подняли). После сохранения правила квота пересчитывается сразу, не дожидаясь интервала.

**Требование к Remnawave.** Доступ режется сквадами, а сквад — это набор инбаундов. Значит, у
обходных нод должны быть **свои инбаунды**, отдельные от безлимитных, и они должны лежать в
отдельном скваде. Если обход и Нидерланды работают на одном и том же инбаунде, снять доступ
только к обходу сквадом невозможно.

**Три режима.** «Тест» — считает и показывает, кого бы перевёл, но ничего не меняет в панели,
**в том числе не пишет описания** — поэтому `{{DESCRIPTION}}` в тесте пустой. «Только счётчик» —
пишет клиентам цифры, никого не переводит: удобно сначала показать счётчик и убедиться, что он
верный. «Боевой» — счётчик плюс перевод при превышении. Новое правило создаётся в тесте.

**Проверить пользователя** — кнопка в карточке правила: по нику показывает, попадает ли он под
правило, сколько натратил, что должно лежать в описании и что лежит на самом деле, и называет
причину расхождения.

**Из карточки пользователя.** Блок «Квоты» показывает все правила и статус человека в каждом,
с кнопкой на каждый случай: «Под квоту» — выдать сквад с лимитом; «Исключить» — доступ остаётся,
но без лимита (для VIP и своих тестов); «Вернуть под квоту»; «Вернуть доступ» — досрочно, если
человек ограничен. В форме пользователя сквад, к которому привязана квота, помечен.

**Схема «База + Обход».** Если у пользователей запасной сквад («База») есть и так, правило его
не добавляет при переводе и не снимает при возврате — панель запоминает, добавляла ли она его сама.

**Ручные правки уважаются.** Если админ сам поменял сквады ограниченному пользователю, в новом
периоде движок это видит и возвращать ничего не будет.

**Показ клиенту.** В описание пользователя пишется строка по шаблону — по умолчанию
«120 из 300 ГБ» или «лимит исчерпан · вернётся 01.10». Remnawave подставляет описание в название
хоста через `{{DESCRIPTION}}`. Сделай информационный хост с названием вроде
`📊 Обход: {{DESCRIPTION}}`, привязанный к инбаунду из **безлимитного** сквада — тогда строка
будет видна в подписке и после исчерпания лимита.

**Баннер в Happ** — вместо хоста-таблички или вместе с ним. Remnawave применяет те же подстановки
к заголовкам ответа подписки, а Happ показывает заголовок `announce` плашкой над списком
серверов. Кнопка в карточке правила дописывает в настройки подписки
`announce: rwEncodeBase64:📊 Обход: {{DESCRIPTION}}` — остальные заголовки не трогаются. Цена: поле «описание» у этих пользователей
занимает RemnaDeck — ручные заметки в нём перезапишутся. Отключается галочкой в правиле.

## Статус-страница для клиентов

Раздел «Статус-страница» (группа «Клиенты»). Клиенты видят общее состояние («все серверы работают» /
«часть недоступна» / «серьёзный сбой»), объявление от админа, по каждой ноде — флаг, публичное имя,
состояние, грубую нагрузку и полоску доступности за 7 дней по 3 часа с аптаймом за 24 часа и неделю,
ниже — сбои за неделю с длительностью.

**Откуда данные.** Из снимков поллера (`snapshots`), публичный запрос в Remnawave не ходит: ответ
считается раз в 30 секунд и отдаётся всем из памяти. Сбоем считается нода без связи дольше 2 минут
подряд. Выключенная нода — «обслуживание», в аптайм не идёт. Нагрузка — онлайн сейчас относительно
обычного пика этой ноды (95-й перцентиль за неделю): «средняя» — онлайн дошёл до обычного пика и в нём
не меньше 10 человек, «высокая» — вышел за пик и не меньше 20, иначе «свободно».

**Что не уходит наружу:** адреса и IP нод, трафик, точный онлайн, внутренние имена (если задано
публичное). Какие ноды показывать и под каким именем — в таблице раздела; по умолчанию видны все
включённые под своими именами.

**Отдельный домен.** Задай в разделе домен (пишется в `.env` как `STATUS_DOMAIN`), A-запись на
сервер и блок в Caddyfile:

```
status.example.com {
    encode gzip
    reverse_proxy remnadeck:8090
}
```

На этом домене панель отдаёт только статус-страницу с корня: `/api/*`, статика админки и WebSocket
отвечают 404, так что клиенты не узнают адрес админки. На домене панели страница открывается по
`/status` — пока она выключена, её видит только вошедший админ (превью).

## Прослойка подписок

Раздел «Прослойка подписок» (группа «Клиенты»). Caddy отдаёт домен подписок в RemnaDeck, тот
проксирует всё в subscription-page и на лету правит ответ клиенту — **ничего не записывая в Remnawave**.

**Тексты пишутся один раз — в Remnawave** (объявление в настройках подписки, названия и описания
хостов). RemnaDeck только подставляет в них свои значения; неизвестные ей подстановки Remnawave
оставляет как есть:

| Подстановка | Что будет |
|---|---|
| `{{RD_QUOTA}}` | счётчик по шаблону правила: «120 из 300 ГБ» / «лимит исчерпан · вернётся 01.10» |
| `{{RD_QUOTA_LEFT}}` `{{RD_QUOTA_USED}}` `{{RD_QUOTA_LIMIT}}` | остаток, израсходовано, лимит, ГБ |
| `{{RD_QUOTA_PERCENT}}` `{{RD_QUOTA_RESET}}` | процент, дата сброса |
| `{{RD_MESSAGE}}` | сообщения автоматизаций (нет в тексте — встают в начало плашки Happ) |
| `…:Имя правила` | значение конкретного правила: `{{RD_QUOTA_LEFT:Обход}}` |

Строка плашки, где все подстановки пустые (человек не под квотой), убирается целиком; хост с
пустыми подстановками — скрывается (настройка). В разделе видно, где в Remnawave ещё стоит
`{{DESCRIPTION}}`; кнопка переводит эти места на `{{RD_QUOTA}}`, вторая — очищает описания
пользователей, где лежит только счётчик, и выключает запись счётчика в описание во всех правилах.
Ручные заметки в описаниях не трогаются.

**Состояние нод.** Хост, все ноды которого без связи, помечается «⚠️ » и по желанию уходит в
конец списка; хосты выключенных нод можно скрыть. Ноды хоста — из привязки в Remnawave, а если её
нет — по совпадению адреса или IP.

Ссылки (base64 / plain) и Xray JSON — Happ, v2rayNG, v2rayN, Streisand — разбираются целиком. В
Mihomo/Clash и sing-box подстановки меняются прямо в тексте, но скрыть хост там нельзя. Любая ошибка
разбора — клиент получает исходный ответ. Заголовки клиента (User-Agent, `x-hwid`, IP) доходят до
Remnawave без изменений. Скрыть хост в подписке не значит закрыть доступ — доступ режут сквады.

Caddyfile с запасным путём: если RemnaDeck не отвечает, подписки идут напрямую.

```
https://sub.example.com {
    encode
    reverse_proxy remnadeck:8090 remnawave-subscription-page:3010 {
        lb_policy first
        lb_try_duration 5s
        fail_duration 30s
    }
}
```

## Баны по HWID и IP

Раздел «Баны» (группа «Клиенты»). Запрос подписки с забаненного устройства (заголовок `x-hwid`) или
адреса (IP или подсеть до /16) прослойка в Remnawave не пропускает: клиент получает заглушку с вашим
текстом — строчками-«серверами» и плашкой Happ, в Clash — YAML, в браузере — страницу. Remnawave даже
не узнаёт об этом устройстве. HWID-бан действует на все аккаунты — против набора пробных подписок с
одного телефона. Кнопка бана есть у каждого устройства в карточке пользователя и в журнале
обновлений подписки (последние 7 дней: кто, IP, HWID, приложение — с поиском).

Бан закрывает только **получение подписки**: уже скачанные конфиги работают, пока у пользователя не
сменить ключи («Новая подписка» в карточке). IP мобильных операторов делят тысячи людей (CGNAT) —
надёжнее банить HWID. Работает, только когда подписки идут через прослойку.

## Автоматизации

Раздел «Автоматизации» (группа «Клиенты»): **условие → действия**. Пока условие выполняется —
действия действуют; перестало (новый период квоты, продлил подписку), автоматизацию выключили или
удалили — откатываются.

- **Условия:** порог квоты (израсходовано ≥ N% по правилу квоты — считает движок квот); срок
  подписки (истекает через ≤ N дней / уже истекла). Можно ограничить пользователями со сквадом.
- **Действия:** переместить из сквада A в B, добавить сквад, убрать сквад (с разрывом соединений на
  выбранных нодах); сообщение в подписке и скрытие хостов — через прослойку, в Remnawave не пишется.

Что именно поменяно в сквадах, запоминается, и откат возвращает ровно это. Если админ за это время
сам поменял сквады пользователю, откат ничего не трогает. Откаты идут от поздних к ранним — цепочки
вроде «80%: A→B, 100%: B→C» разматываются правильно. Пользователь, которого автоматизация сняла
со «сквада с лимитом», остаётся под квотой — счётчик продолжает считаться.

**Разовые события.** Условие «обновил подписку, в User-Agent есть слово» (несколько — через
запятую, регистр не важен) срабатывает в прослойке **один раз на пользователя** и не откатывается.
Действия: продлить подписку на N дней (от даты окончания, а если она уже прошла — от сегодня;
Remnawave сама вернёт истёкшего в ACTIVE), добавить или убрать сквад. Два одновременных обновления
бонус дважды не дадут; если Remnawave не ответила — начислится при следующем обновлении.
User-Agent задаёт клиент, так что это промо-механика, а не защита. В тесте журнал пишет «сработала бы».

Режим «тест» только показывает, кого затронет; «боевой» применяется сразу после сохранения, дальше —
раз в 5 минут и сразу после прогона квот. У каждой автоматизации — журнал: кому применено, у кого
откат, где откат пропущен. Если действия квоты заданы автоматизациями, поставь правило квоты в режим
«только счётчик», иначе его встроенный перевод сработает вдобавок.

## Что делается по API, а что по SSH

Через API Remnawave панель заводит и правит **записи** нод и хостов. Всё, что живёт на самом
сервере — контейнер ноды, сертификаты, nginx — по API недоступно, поэтому для обновления,
Hysteria2 и CDN нужен SSH. Сервер добавляется в разделе «Серверы»: хост, пользователь
(лучше root, иначе нужен sudo без пароля), пароль или приватный ключ и путь к каталогу ноды
с `docker-compose.yml`. Доступы шифруются ключом `CRYPT_KEY` из `.env` и лежат в `data/panel.db`.
Наружу они не отдаются никогда — ни в одном ответе API их нет.

SSH-доступ задаётся у каждой ноды: в форме ноды есть блок «SSH-доступ к серверу ноды», а в карточке
ноды — кнопка «Указать SSH-доступ», если он ещё не задан. Как только доступ есть, в карточке
появляются «Обновить ноду», «Hysteria2», «Настроить CDN», «Состояние CDN», «Проверить SSH» и
«Отвязать сервер». Раздел «Серверы» показывает всё то же самое списком — удобно, когда машин много.

### Установка ноды на чистый сервер

В форме «Добавить ноду» заполни блок SSH и отметь «Установить ноду на этот сервер». Панель
заведёт запись в Remnawave, запомнит доступ и тут же выполнит на сервере установку: поставит
docker (официальный скрипт get.docker.com), создаст каталог ноды, положит `docker-compose.yml`
с образом `remnawave/node:latest` и `.env` с ключом этой панели, откроет порт в ufw (если он
активен — только для IP панели) и запустит контейнер. В конце покажет, слушается ли порт, и хвост лога.

Ключ берётся из `GET /api/keygen` и пишется под обоими именами — `SSL_CERT` и `SECRET_KEY`,
потому что до версии 2.9 нода читала первое, а с 2.9 — второе. Значение одно и то же.

Если в каталоге уже есть `docker-compose.yml`, установка останавливается и ничего не трогает.
Перезаписать можно из карточки ноды: «Установить ноду» → «Перезаписать». Старый compose-файл
в любом случае копируется в `.bak.<таймстемп>`.

Отдельная галочка «BBR и лимиты» кладёт `/etc/sysctl.d/99-remnadeck.conf` (fq + bbr, буферы
TCP, tcp_fastopen, диапазон портов, `fs.file-max`) и поднимает `nofile` в limits.conf.

Облачный фаервол панель не трогает: на GCP, Hetzner и Oracle порт ноды нужно открыть у хостера
руками — скрипт об этом предупреждает.

### Обновление нод

Кнопка «Обновить» на сервере или «Обновить все ноды» выполняет `docker compose pull` и
`up -d` в каталоге ноды, показывает версию образа до и после, состояние контейнера и хвост лога.
При обновлении всех серверов панель идёт по ним по очереди и в конце пишет, сколько прошло удачно.

### Hysteria2

Повторяет логику `remnautility.sh`: выпускает сертификат Let's Encrypt (HTTP-01, при занятом
80 порту временно останавливает nginx), монтирует `fullchain.pem` и `privkey.pem` в
`/var/lib/remnawave/configs/xray/ssl/`, переводит образ на `latest` и пересоздаёт контейнер.
`docker-compose.yml` перед правкой копируется в `.bak.<таймстемп>`. Сам инбаунд Hysteria2
включается в профиле ноды в Remnawave — панель туда не лезет.

### CDN

Конфиг делится на две части.

**Общая** — `/etc/nginx/conf.d/rd-cdn-common.conf`, панель ставит и обновляет её сама перед
каждым сайтом. Там всё, что обязано жить на уровне `http{}`: буферы заголовков под Yandex
(uplink едет в `X-Client-Data`), `client_max_body_size` под Beeline (uplink телом), keepalive
для соединений от CDN, `map` реального IP клиента из последнего элемента `X-Forwarded-For` и
общие `proxy_set_header`. Если какая-то директива уже задана в `nginx.conf`, панель гасит свою
копию (помечает `#rd-disabled`) и пишет об этом в лог задачи — `nginx -t` не падает.

**Посайтовая** — `/etc/nginx/sites-available/rd-cdn-<шаблон>-<домен>`: `upstream` с keepalive,
80-й блок под ACME и редирект, 443-й с сертификатом и одним `location` на рабочий путь,
остальное — 404. Свой `proxy_set_header` внутри `location` отменил бы все заголовки из общего
конфига, поэтому в шаблонах их нет.

Встроенные шаблоны: Yandex, Beeline, Timeweb, VK и универсальный — у каждого свой путь и порт
по умолчанию, у Timeweb включён `default_server` (ловит запросы без SNI). Свои добавляются и
правятся там же. Плейсхолдеры: `{{server_names}}`, `{{domain}}`, `{{path}}`, `{{port}}`,
`{{upstream}}`, `{{default}}`, `{{cert}}`, `{{key}}`.

Доменов у одного CDN может быть несколько (через запятую) — первый основной, сертификат
выписывается сразу на все. Галочка «Сертификат только на основной домен» оставляет остальные
только в `server_name`: так добавляется техдомен Timeweb, который смотрит на CDN, а не на сервер,
и сертификат на него не выпустить. Для шаблона Timeweb галочка стоит по умолчанию. Несколько CDN на одной ноде — просто несколько доменов, каждый
своим файлом. «Снять» удаляет конфиг и по желанию сертификат.

### Как выпускается сертификат

По умолчанию — HTTP-01. Перед запуском certbot панель сверяет домен публичным резолвером
(1.1.1.1, запасной 8.8.8.8) со внешним IP сервера и показывает все найденные A-записи и CNAME.
Не совпало — останавливается и ничего не трогает: так не сгорают лимиты Let's Encrypt и не
портится docker-compose ноды.

Если домен уже за CDN или 80-й порт закрыт, HTTP-01 не пройдёт в принципе. На этот случай в
формах Hysteria2 и CDN есть поле «Токен Cloudflare API»: с ним выпуск идёт через DNS-01,
адрес домена роли не играет. Токену нужны права Zone:DNS:Edit на соответствующую зону. Панель
токен не хранит — он только передаётся на сервер и ложится в `/etc/letsencrypt/rd-cloudflare.ini`
с правами 600, откуда его берёт и автопродление.

## Подключение к Remnawave

- Та же машина: `http://remnawave:3000`. Remnawave рвёт запросы без `X-Forwarded-For` и
  `X-Forwarded-Proto: https`, панель добавляет их сама (режим «Автоматически»).
- Другой сервер: `https://panel.example.com`.
